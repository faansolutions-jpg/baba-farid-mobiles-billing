# Deploy — Baba Farid Mobiles billing backend + apps

Goal: put the backend on a public host so the phone app can reach it, then
rebuild the APK with the backend URL, and build the Windows app.

Everything is prepared in this repo. The only steps that need the owner's
own accounts are Step 1 (GitHub) and Step 2 (Render). Nothing is deployed
yet — no public URL exists until those two steps are done.

## What is already done (in this repo)

- `render.yaml` — Render Blueprint: free web service + free PostgreSQL 16.
  JWT secrets are auto-generated by Render (`generateValue: true`); they are
  never in this repo. Login rate limit is the production default (5 / 15 min).
- `scripts/render-migrate.sh` — runs schema + catalog migration + seed on
  the hosted DB before each deploy (schema only on first deploy).
- `.github/workflows/windows-build.yml` — builds the Windows release on a
  Windows runner and uploads `baba_farid_mobiles.exe` as an artifact.
- `.github/workflows/apk-build.yml` — rebuilds the APK with a given backend
  URL (manual trigger).
- The code is committed locally (git). No remote is set yet.
- Backend verified locally: `/health` returns `{"ok":true,"status":"up"}`,
  login works (`+923299966771` / `admin123`), catalog = 1,726 items.

## Step 1 — Put the code on GitHub (needs the owner's GitHub account)

1. Create a GitHub account at https://github.com/signup (if there is none).
2. Create a new EMPTY repository, e.g. `baba-farid-mobiles-billing`
   (do NOT add a README/license/.gitignore — the repo already has them).
3. On this machine, connect git to GitHub and push:
   ```
   cd ~/workspace/mobile-shop-billing-system
   gh auth login            # sign in with the GitHub account (browser)
   git remote add origin https://github.com/<username>/baba-farid-mobiles-billing.git
   git push -u origin main
   ```
   (`main` is the current branch. If `gh` is not installed, use
   `git remote add origin ...` + `git push` and sign in when asked.)

## Step 2 — Deploy the backend on Render (free tier)

1. Create a Render account at https://dashboard.render.com/register
   (sign up with GitHub is easiest — it links the repo automatically).
2. Dashboard -> New -> **Blueprint** -> select the GitHub repo from Step 1.
3. Render reads `render.yaml` and shows two resources:
   `baba-farid-mobiles-backend` (web service, free) and
   `baba-farid-mobiles-db` (PostgreSQL, free). Click **Apply**.
4. Wait for the deploy to finish (first deploy takes a few minutes; the
   pre-deploy step creates the tables, loads the 1,726-item catalog and
   the seed users/products). Check the service **Logs** for
   "Migration complete" and "listening on port ...".
5. Open the service URL and check health:
   `https://baba-farid-mobiles-backend.onrender.com/health`
   must return `{"ok":true,"data":{"status":"up",...}}`.
6. The public backend base URL for the app is:
   `https://baba-farid-mobiles-backend.onrender.com/api/v1`
   (Render gives the exact hostname on the service page — use that one.)

Free-tier notes: the free web service sleeps after 15 min idle (first
request after idle takes ~30-60s to wake). The free PostgreSQL expires
after 90 days — back it up or upgrade before then.

## Step 3 — Rebuild the APK with the deployed backend URL

Option A — on this machine (needs the Flutter SDK at ~/flutter_sdk):
```
cd ~/workspace/mobile-shop-billing-system/mobile_app
export PATH="$HOME/flutter_sdk/flutter/bin:$PATH"
flutter build apk --release \
  --dart-define=API_BASE_URL=https://baba-farid-mobiles-backend.onrender.com/api/v1
cp build/app/outputs/flutter-apk/app-release.apk \
   ~/workspace/your_files/baba-farid-mobiles-app-release.apk
```

Option B — GitHub Actions (no local build needed):
Actions tab -> "Build Android APK" -> Run workflow -> paste the backend
base URL from Step 2 step 6 -> the APK downloads from the run's Artifacts.

Default login in the app: `+923299966771` / `admin123` (change after first login).

## Step 4 — Build the Windows app (GitHub Actions)

GitHub Actions tab -> "Build Windows release" -> Run workflow.
When it finishes, download the `baba-farid-mobiles-windows` artifact from
that run, unzip it on a Windows PC, and run `baba_farid_mobiles.exe`.

Or build directly on a Windows PC with Flutter installed:
```
flutter build windows --release
REM output: build\windows\x64\runner\Release\baba_farid_mobiles.exe
```

## If Render is not wanted

Any Node.js + PostgreSQL host works (Railway, Fly.io, a VPS). The backend
needs: `npm ci --include=dev && npm run build`, then `node dist/server.js`
with env vars `NODE_ENV=production`, `DATABASE_URL`, `JWT_ACCESS_SECRET`,
`JWT_REFRESH_SECRET`, `PORT` (host-provided), and the SQL files
`database/schema.sql`, `database/migrations/001_accessories_catalog.sql`,
`database/seed.sql` run once against the hosted DB.
